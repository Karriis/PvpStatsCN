# pvplogs 前端体验与视觉实施计划

> 状态：首版视觉与核心交互已实现
> 更新日期：2026-08-26
> 上位方案：[pvplogs-platform-plan.md](./pvplogs-platform-plan.md)

## 0. 已确认的首页覆盖项

用户在实现阶段对原首页方案作了明确覆盖：顶部仅保留登录与主题切换；首页采用 Logo、单行打字机 Hero 和统一搜索；累计对局移动至公共 Footer；移除首页数据概览、覆盖玩法、宣传说明和顶部品牌 Logo。Footer 显示 `PVPLogsCN / Karriis / 累计收录 / 申请隐藏 / 隐私政策 / Github`。这些覆盖项优先于下文 3.1 的早期设想。

当前实现还包含：六维玩家对局筛选与 URL 恢复、三种玩法详情、72 人桌面冻结列与移动端展开行、管理后台折叠式桌面侧栏、OpenAPI 类型生成、Storybook、axe、减少动效和 390/768/1280/1440/1920 多视口回归。PingFang 网页再分发授权未确认，因此首版依法使用系统中文无衬线字体回退，不打包 PingFang 字体文件。

## 1. 设计方向

- 参考 [TripleD UI](https://github.com/moumen-soliman/uitripled) 的视觉语言，不复刻其首页布局：
  - 白底、黑字、极浅灰边框。
  - 中等圆角、局部胶囊控件。
  - 克制阴影、点阵纹理和 Motion 动效。
  - 不使用巨型 Hero、宣传式大标题、卡片墙和大面积游戏背景。
- 默认浅色主题，提供中性近黑的深色主题；主题选择写入 Cookie，避免 SSR 闪烁。
- 黑白作为结构色，只为胜负、排名、阵营、职业职能、警告和图表序列使用低饱和功能色。
- 结果表达保持客观，通过字重、小图标和少量颜色轻微强调，不使用庆祝彩带或大面积胜负背景。

## 2. 设计系统与组件规范

### 2.1 视觉令牌

- 浅色背景接近纯白，深色背景接近 `#0A0A0A`，不使用蓝灰电竞底色。
- 卡片、表格容器和弹窗使用 12–16px 圆角；搜索框、筛选、标签和状态使用胶囊形。
- 细边框是主要层级手段；阴影只用于悬浮层和当前聚焦元素。
- 点阵纹理只用于首页搜索、玩家概览和空状态；数据表与后台使用纯色背景。
- 玻璃和背景模糊只用于吸顶导航、搜索下拉、抽屉、弹窗及悬浮工具栏。
- 首页与账户页使用窄版居中布局；玩家档案使用中等宽度；72 人表格与后台可扩展到超宽屏。

### 2.2 字体

- 本地托管 PingFang SC 的 Regular、Medium、Semibold WOFF2。
- 字体按中文 UI 词库进行子集化；只预加载 Regular，其余字重按需加载。
- 标题仍使用苹方，通过字重、紧凑字距和编辑式排版形成层级，不额外混用装饰字体。
- ID、时间和核心数值启用等宽数字；公开 ID 可使用等宽回退字体。
- PingFang 字体生产发布前必须完成授权检查；无法确认网页再分发授权时，替换为合法自托管的中文无衬线字体。

### 2.3 动效与基础组件

- 常规过渡控制在 120–220ms；仅浮层和搜索展开允许轻微弹性。
- 表格排序、分页和筛选以即时响应为先，不做逐行进入动画。
- 完整支持 `prefers-reduced-motion`。
- 使用 shadcn/ui 作为基础组件，选择性改造 TripleD 的 Button、Tabs、Dialog、Tooltip、Delete、Command Palette、Sign-in Card 和 Dashboard 结构。
- 图标统一使用 Lucide；游戏职业图标克制保留，模式和地图素材单色化，不使用大面积截图。
- 数据表使用 TanStack Table；图表使用 shadcn Chart/Recharts。

## 3. 公开端信息架构

### 3.1 首页 `/`

- 轻量吸顶顶部栏：品牌占位标识、全局搜索、模式入口、登录/账户、主题切换。
- 首屏核心是统一智能搜索，不放宣传式大标题：
  - 自动识别公开对局 ID。
  - 输入角色名时返回带服务器的玩家候选。
  - 支持键盘上下选择和回车进入。
  - 不通过曾用名返回搜索结果。
- 搜索下方展示克制的全站汇总：
  - 已收录对局数、公开玩家数。
  - 三种模式占比。
  - 近期数据覆盖情况。
- 不展示最近玩家、个人排行榜或最新对局动态。

### 3.2 玩家档案 `/players/[publicId]`

- 最近活跃角色作为页面主体。
- 顶部展示当前角色、服务器、近期模式和关键指标；账号总览与其他角色通过紧凑切换器进入。
- 曾用名和历史服务器不公开。
- 内容按模式切换，展示：
  - 场次、胜率或平均排名。
  - 常用职业、核心均值。
  - 少量趋势和分布图。
  - 历史对局。
- 历史对局：
  - 桌面端使用紧凑表格。
  - 移动端转换为结构化列表。
  - 支持角色、模式、职业、地图、结果和时间筛选。
  - 筛选状态同步到 URL。
- 无公开 PvP 对局的身份观察记录不生成该页面。

### 3.3 对局详情 `/matches/[publicId]`

- 使用 `概览 / 计分板 / 时间线` 页内标签，当前标签写入 URL。
- 对局摘要和筛选工具栏在内容区吸顶。
- 概览展示模式、地图、时间、结果、队伍汇总和少量关键指标。
- 纷争前线计分板：
  - 默认按排名分为三队。
  - 可切换全体 72 人视图。
  - 桌面冻结玩家和职业列，其余列可横向滚动。
  - 移动端只显示关键列，通过行展开查看完整数据。
- 水晶冲突和烈羽争锋采用相同骨架，并显示各自专属指标。
- 匿名玩家显示为仅在该场稳定的 `匿名玩家 A01` 等编号，禁止跨对局关联。
- 不提供公开 CSV、JSON 或玩家历史批量导出，只提供复制链接。
- 搜索结果、玩家档案和对局详情统一设置 `noindex`。

## 4. 账户与管理后台

### 4.1 账户流程

- 登录、注册、邮箱验证、找回密码、插件绑定和数据库导入使用独立专注页面。
- 表单采用窄栏实色卡片；背景可使用极浅点阵，不放营销内容。
- 错误、等待、成功和过期状态原位反馈。
- 账户中心提供设备令牌、插件绑定、导入任务和安全设置，不允许修改战绩数据。

### 4.2 管理后台

- 与公开端共享设计令牌和组件，但提高密度、取消点阵、减少透明层与动效。
- 使用可折叠左侧栏，分组为：
  - 概览
  - 用户与设备
  - 对局与来源
  - 身份与曾用名
  - 隐私申请
  - 数据库导入
  - 审计日志
  - 系统设置
- 内容区顶部显示面包屑、后台搜索、告警和账户菜单。
- 大型列表使用服务端分页、排序和筛选；危险操作需要确认层并使用明确功能色。
- 审核员看不到无权限模块，不能仅靠前端隐藏按钮实现权限控制。

## 5. 前端接口、测试与验收

### 5.1 数据接口

- 从 Go API 的 OpenAPI 文档生成 TypeScript 类型和请求客户端。
- 核心视图模型：
  - `PublicSearchResult = MatchResult | PlayerResult`
  - `PlayerProfileView`
  - `CharacterSummary`
  - `MatchDetailView = CCMatch | FLMatch | RWMatch`
  - `ScoreboardRow`
  - `TimelineSeries`
  - `AdminTablePage<T>`
- 公共页面优先使用服务端渲染；搜索建议、筛选、表格和图表使用客户端交互。
- 加载采用骨架屏；接口错误区分未找到、无权限、被匿名化、数据隔离和服务异常。

### 5.2 测试

- Storybook 覆盖基础组件、表格、图表、状态页及浅色/深色主题。
- Playwright 覆盖首页搜索、玩家切换、对局标签、72 人表格、登录绑定和后台审批。
- 使用 axe 检查 WCAG 2.2 AA、键盘操作、焦点状态和颜色对比度。
- 对 375px、768px、1280px、1440px 和超宽屏执行视觉回归。
- 验证长角色名、多个小号、72 人数据、空时间线、匿名玩家和极端数值不会破坏布局。
- 验证主题切换无闪烁、减少动效有效、筛选 URL 可恢复、匿名信息不会进入 HTML 元数据。
- 性能目标：公开页面移动端 LCP 不高于 2.5 秒，避免一次加载完整 PingFang 字体包和非当前标签图表。

## 6. 明确假设和首版边界

- 正式品牌、Logo、域名和公开文案后续确定，首版使用 `pvplogs` 占位。
- PingFang 字体按指定采用本地托管，但生产发布以取得合法网页分发授权为前提。
- 首版不包含排行榜、最近玩家流、批量导出、深度雷达分析或用户编辑战绩。
- 本计划是总体平台计划的补充，不改变既定的 Go、PostgreSQL、身份模型和隐私规则。
